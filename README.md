# Resume Requests Consumer

English | [Español](README.es.md)

AWS Lambda SQS consumer that stores resume requests in DynamoDB and sends a
notification through Gmail SMTP after persistence.

## Responsibilities and boundaries

This consumer owns:

- deserializing resume request messages from SQS;
- conditionally storing each request in DynamoDB;
- generating the persistence timestamp in ISO-8601 format;
- notifying the configured recipient through Gmail SMTP;
- returning partial batch failures so SQS retries only failed records.

The producer owns the message schema and validation. Infrastructure provisioning,
queue configuration, DynamoDB table creation, secrets, IAM, and the Lambda event
source mapping live outside this repository.

## Application structure

```text
.
├── .github/workflows/              # Continuous integration
├── src/
│   ├── clients/
│   │   ├── aws/                    # DynamoDB integration and AWS errors
│   │   └── gmail/                  # Gmail SMTP integration
│   ├── config/                     # Environment-backed configuration
│   ├── handlers/                   # SQS Lambda adapter
│   ├── messages/                   # Producer message contract
│   └── services/                   # Consumer orchestration
├── test/                           # Unit tests mirroring src responsibilities
├── .env.example                    # Local configuration template
├── index.mjs                       # Lambda composition root (index.handler)
└── package.json                    # Runtime metadata and commands
```

The root handler only wires dependencies. Provider-specific behavior stays in
`clients`, message deserialization stays in `messages`, and processing order stays
in `services`.

## Message contract

```json
{
  "requestId": "UUID-v7",
  "requestedAt": "2026-08-30 15:43:35",
  "ipHash": "sha-256-hash",
  "email": "user@example.com",
  "subscribeToUpdates": true,
  "timestamp": 1788122615000
}
```

The incoming numeric `timestamp` belongs to the producer contract. DynamoDB stores
a new ISO-8601 `timestamp` generated by this Lambda when the item is persisted.

## Configuration

| Variable | Required | Default | Sensitive | Purpose |
| --- | --- | --- | --- | --- |
| `DYNAMODB_TABLE_NAME` | Yes | None | No | Target DynamoDB table |
| `GMAIL_SMTP_APP_PASSWORD` | Yes | None | Yes | Google App Password for SMTP authentication |

Keep `GMAIL_SMTP_APP_PASSWORD` in the Lambda environment through an encrypted
deployment configuration or a secret manager. Never commit it or use the normal
Google account password.

The SMTP host (`smtp.gmail.com`), SSL port (`465`), account, sender, recipient,
and subject are application constants in `src/config/environment.mjs`.

## Local verification

Requirements: Node.js 20 or later.

```bash
npm install
npm run check
npm test
```

Tests use local fakes and do not call DynamoDB or Gmail.

## Lambda configuration

Use `index.handler` as the Lambda handler. Enable SQS partial batch responses by
including `ReportBatchItemFailures` in the event source mapping.

## Deployment

`.github/workflows/deploy.yml` tests and packages the application on pushes and
pull requests. A push or manual run from `main` deploys the package to the
existing Lambda through GitHub OIDC and the `production` environment.

Configure these non-sensitive GitHub Environment variables in `production`:

| Variable | Value |
| --- | --- |
| `AWS_ROLE_ARN` | `arn:aws:iam::506126099559:role/portfolio-github-deploy-resume-requests-consumer` |
| `AWS_REGION` | `us-east-1` |
| `LAMBDA_FUNCTION_NAME` | `portfolio-resume-requests-consumer` |

GitHub Actions owns the deployment package and subsequent code updates. Terraform
continues to own Lambda configuration, IAM, environment variables, the SQS event
source mapping, logs, and bootstrap code.
